Supervision & Auto-Remédiation Kubernetes Next-Gen

Kusanagi est une plateforme unifiée haute performance conçue en Rust (Axum + Tokio) combinant la supervision temps réel de clusters Kubernetes, la gestion GitOps ArgoCD, l'analyse réseau eBPF Cilium/Hubble, le scanning de vulnérabilités Trivy enrichi par IA, et l'intégration multi-infrastructures (Proxmox, Home Assistant).

Architecture Hexagonale & Design

Kusanagi est structuré selon les principes du Clean Code & de l'Architecture Hexagonale (Ports & Adapters), garantissant un découplage total entre la logique métier, les protocoles d'accès (HTTP Axum, WebSockets) et les adaptateurs d'infrastructure (Kubernetes, S3, Proxmox, LLM).

Guide d'Installation & Démarrage

Exécutez Kusanagi directement sur votre machine avec Cargo :

BASH 
# 1. Cloner le dépôt
git clone https://github.com/JZacharie/Kusanagi.git
cd Kusanagi

# 2. Configurer les variables d'environnement
cp .env.template .env

# 3. Lancer l'application en mode développement
cargo run

# 4. Ouvrir l'interface web
open http://localhost:8080

Exécutez Kusanagi sous forme de conteneur autonome avec Docker :

DOCKER 
# Construire l'image Docker optimisée
docker build -t kusanagi:latest .

# Lancer le conteneur en mappant le port 8080 et le kubeconfig
docker run -d \
  --name kusanagi \
  -p 8080:8080 \
  -v ~/.kube/config:/root/.kube/config:ro \
  -e RUST_LOG=info \
  kusanagi:latest

Déploiement sur votre cluster Kubernetes via le Helm Chart officiel :

HELM 
# Ajouter le repo Helm
helm repo add kusanagi https://jzacharie.github.io/helmscharts
helm repo update

# Installer Kusanagi dans le namespace 'kusanagi'
helm install kusanagi kusanagi/kusanagi \
  --namespace kusanagi \
  --create-namespace \
  --set ingress.enabled=true \
  --set ingress.host=kusanagi.example.com

Déployez Kusanagi via une ressource Application ArgoCD :

YAML 
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: kusanagi
  namespace: argocd
spec:
  project: default
  source:
    repoURL: 'https://github.com/JZacharie/helmscharts.git'
    targetRevision: HEAD
    path: charts/kusanagi
  destination:
    server: 'https://kubernetes.default.svc'
    namespace: kusanagi
  syncPolicy:
    automated:
      prune: true
      selfHeal: true

Guide de Configuration

Kusanagi se configure facilement via des variables d'environnement ou le fichier kusanagi.toml :

ENV / CONFIGURATION 
# --- Serveur & Logs ---
BIND_ADDR=0.0.0.0:8080
RUST_LOG=info,kusanagi=debug
KUSANAGI_RATE_LIMIT_PER_SECOND=10000

# --- Intégration Kubernetes ---
KUBECONFIG=~/.kube/config
POD_NAMESPACE=kusanagi

# --- GitOps & ArgoCD ---
ARGOCD_SERVER=argocd-server.argocd.svc:443
ARGOCD_TOKEN=your-argocd-jwt-token

# --- Sécurité & Trivy ---
TRIVY_SERVER_URL=http://trivy-server.trivy-system.svc:8080
S3_ENDPOINT=http://minio.storage.svc:9000
S3_BUCKET_SECURITY_REPORTS=kusanagi-security-reports
S3_ACCESS_KEY=your-access-key
S3_SECRET_KEY=your-secret-key

# --- Réseau & Hubble (eBPF) ---
HUBBLE_RELAY_URL=http://hubble-relay.kube-system.svc:80

# --- Assistant IA & LLM ---
LITELLM_URL=http://litellm.litellm.svc:4000
LITELLM_API_KEY=your-litellm-key
OLLAMA_URL=http://ollama.ai.svc:11434/api/generate
OLLAMA_MODEL=ministral-3:14b

Référence des Endpoints API

GET /health
Vérification de santé du serveur Kusanagi et de ses dépendances

Réponse type :

{
  "status": "healthy",
  "version": "0.3.0",
  "uptime_seconds": 34820,
  "kubernetes_connected": true
}
GET /metrics
Exposition des métriques au format standard Prometheus

Export de compteurs de requêtes, latence, hits de cache et gauges de supervision.

GET /api/k8s/pods
Liste et état en temps réel de tous les Pods du cluster

Retourne le nom, namespace, status (Running, CrashLoopBackOff), restarts et métriques CPU/RAM.

GET /api/k8s/nodes
État, capacité et allocations des 16 nœuds du cluster

Inclut les conditions Ready/MemoryPressure/DiskPressure, CPU allocatable, Pod capacity.

GET /api/argocd/status
État de santé et de synchronisation des 183 applications ArgoCD

Statuts Synced, OutOfSync, Healthy, Degraded.

POST /api/argocd/sync
Déclenchement d'une resynchronisation GitOps pour une application

Payload JSON : {"app_name": "kusanagi", "prune": true}

GET /api/security/vulnerabilities
Synthèse globale des vulnérabilités de conteneurs scannées par Trivy

Répartition par sévérité : Critical, High, Medium, Low avec score CVSS.

GET /api/cilium/flows
Flux réseau eBPF en direct collectés via Hubble Relay

Permet de visualiser les communications inter-services et les paquets droppés.

POST /api/chat
Assistant conversationnel IA avec contexte en direct du cluster

Payload JSON : {"message": "Pourquoi le pod trivy est en CrashLoopBackOff ?"}

WS /api/ws/notifications
Flux d'événements et d'alertes en temps réel via WebSocket natif Axum

Diffusion en push des changements d'état de Pods, alertes Prometheus et incidents.

Déploiement Kubernetes & RBAC

Voici le manifeste RBAC minimal requis pour exécuter Kusanagi avec les permissions de lecture sécurisées :

YAML · RBAC CONFIGURATION 
apiVersion: v1
kind: ServiceAccount
metadata:
  name: kusanagi
  namespace: kusanagi
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: kusanagi
rules:
  - apiGroups: [""]
    resources: ["pods", "nodes", "services", "events", "persistentvolumes", "persistentvolumeclaims"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["apps"]
    resources: ["deployments", "statefulsets", "daemonsets"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["batch"]
    resources: ["cronjobs", "jobs"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["networking.k8s.io"]
    resources: ["ingresses"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: kusanagi
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: kusanagi
subjects:
  - kind: ServiceAccount
    name: kusanagi
    namespace: kusanagi
